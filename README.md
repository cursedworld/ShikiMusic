# ShikiMusic

**Русский** · [English](README.en.md)

Музыкальный плеер на Flutter для **Windows, Android и Linux**.
Локальная библиотека, клипы, синхронные тексты, плейлисты, статистика
и Discord Rich Presence. Для повседневного прослушивания не нужны аккаунт
и постоянно работающий сервер. Linux-версия проверена на Arch Linux.

## Возможности

- Воспроизведение скачанных MP3, очередь, перемешивание, повтор и избранное.
- Скачивание MP4-клипов и локальное воспроизведение видео; видео можно отключить.
- Синхронные LRC-тексты и отдельный полноэкранный режим.
- Плейлисты с собственными обложками и круглым предпросмотром кадрирования.
  Треки располагаются в порядке добавления в плейлист.
- Страницы исполнителей с биографией, альбомами и совместными треками
  при наличии соответствующих данных в каталоге.
- Скачивание всех треков из списка или альбома с очередью загрузок.
- Поиск и импорт через отдельный сервер: отдельные треки, выбранные записи
  по ссылке и YouTube / YouTube Music-плейлисты по ссылке.
- Проверка обновлений каталога и предложения обновить скачанные файлы.
- Локальная статистика прослушивания без регистрации.
- Перенос библиотеки между устройствами через ZIP-архив.
- Настройка акцентного цвета, собственного фона и языка интерфейса.
  Доступны русский, английский и японский; полнота перевода зависит от раздела.
- Системное управление воспроизведением на настольных платформах и Android.

Каталоги `ios`, `macos` и `web` в исходниках не означают подтверждённую
поддержку этих платформ.

## Discord

На настольных платформах плеер передаёт Rich Presence с типом активности
**«Слушает»**: трек, исполнители и информация о воспроизведении.
В настройках можно включить текущую строку текста в компактном статусе
и отключить кнопку GitHub.

Порядок поиска обложек: **iTunes → Deezer → Last.fm**.
Если подходящая обложка трека не найдена, плеер пробует существующую
анимированную обложку альбома через **MusicBrainz + Cover Art Archive**.
Затем используются запасные изображения: публичная обложка из каталога,
фото исполнителя или значок плеера. Обложка трека имеет приоритет над анимацией.

Нужны запущенный настольный Discord и разрешённый показ активности.
Поиск картинок работает напрямую из плеера, без локального сервера.
Для поиска и загрузки картинок нужен интернет. Изображения из `localhost`
или домашней сети Discord получить не сможет. Наличие обложек и анимаций
зависит от внешних каталогов.

## Библиотека и сервер

Серверная часть распространяется отдельно и **не входит в этот репозиторий**.
Она нужна для получения каталога, поиска, импорта и скачивания новых треков,
клипов и обновлений. Сборка плеера не включает сервер и готовую музыкальную библиотеку.

После скачивания музыка, клипы и сохранённые тексты доступны без сервера.
Плейлисты, избранное, настройки и статистика хранятся на устройстве.

Адрес сервера меняется в настройках. Значение по умолчанию —
`http://127.0.0.1:8000`. Его также можно задать при запуске или сборке:

```bash
flutter run -d windows --dart-define=SHIKI_SERVER_URL=http://127.0.0.1:8000
```

На Android `127.0.0.1` означает сам телефон. Для сервера на компьютере укажите
адрес, доступный телефону.

При доступном сервере открытый плеер проверяет изменения примерно раз в
12 секунд. Метаданные обновляются в библиотеке, а для изменившихся скачанных
файлов предлагается загрузка новой версии. Если обновляемый MP3 сейчас играет,
новый файл применяется при следующем запуске трека.

## Плейлисты и статистика

Обычная замена сборки сохраняет библиотеку, если приложение использует прежнюю
папку данных. По умолчанию это `ShikiMusic` в каталоге документов,
предоставленном системой. На настольных ОС — обычно папка документов пользователя.

Кнопка **«Очистить кэш»** очищает временные изображения, сохраняя плейлисты,
избранное, статистику и скачанные MP3/MP4. Удаление данных приложения средствами
ОС — другая операция: перед ней сделайте резервную копию.

Статистика доступна из настроек и хранится локально в SQLite: время прослушивания,
популярные треки и исполнители, активность по дням и время использования приложения.
Периоды: 7 дней, 30 дней, текущий год, всё время или свой диапазон.
Есть отдельные экспорт и импорт статистики. Паузы и перемотка не учитываются
как прослушанное время. История собирается с момента использования этой функции;
прошлые прослушивания автоматически не восстанавливаются.

## Перенос и резервная копия

1. Откройте **Настройки → Перенос и резервная копия → Создать архив**.
2. Выберите, включать ли MP3/MP4. Для переноса офлайн-библиотеки включите медиафайлы.
3. Перенесите ZIP на другое устройство.
4. Выберите архив в том же разделе плеера и перезапустите приложение для применения.

Архив включает каталог, плейлисты с обложками, избранное, тексты, настройки
и статистику. Серверная БД, учётные данные Django и исполняемые файлы не включаются.

Импорт объединяет списки, сохраняет порядок треков и не заменяет существующую
музыку. Применение настроек выбирается отдельно. Повторный импорт не удваивает
статистику; конфликт ID разных библиотек останавливает импорт.
Ожидающий импорт можно отменить. Перед применением исходные JSON сохраняются
в папке `transfer_restore_*` внутри данных плеера.

Используется потоковый ZIP без дополнительного сжатия: до 64 ГБ всего,
до 8 ГБ на медиафайл. Импорт принимает архивы, созданные самим плеером;
стороннее пересжатие ZIP не поддерживается. Экспорт и проверка работают
вне UI-потока. Для импорта нужно место под распаковку и копии добавляемых файлов.

**Архив личный:** он может содержать адрес сервера и историю прослушивания.
Не публикуйте его вместе с исходниками.

## Сборка из исходников

Нужен Flutter SDK с Dart, совместимым с `^3.11.1` в
[`pubspec.yaml`](pubspec.yaml). Нативные зависимости устанавливаются отдельно
для каждой платформы. После установки инструментов:

```bash
git clone https://github.com/cursedworld/ShikiMusic.git
cd ShikiMusic
flutter doctor -v
flutter pub get
```

### Windows

Установите [инструменты Flutter для Windows](https://docs.flutter.dev/platform-integration/windows/setup),
включая Visual Studio с компонентом **Desktop development with C++**.

```bash
flutter build windows --release
```

Результат: `build/windows/x64/runner/Release/Shiki.exe`.
Переносите **всю папку `Release`**, включая `data` и DLL, а не только EXE.

### Android

Настройте Android SDK и проверьте его через `flutter doctor -v`.

```bash
flutter build apk --release
```

Результат: `build/app/outputs/flutter-apk/app-release.apk`.
В текущей конфигурации release подписывается debug-ключом. Для собственной
публикации настройте постоянный ключ подписи; для обновления установленного
приложения сохраняйте прежние application ID и ключ.

### Arch Linux

Собирайте Linux-версию в Linux. Windows-сборка не создаёт Linux-бинарник.
Установите Flutter SDK и зависимости:

```bash
sudo pacman -S --needed clang cmake ninja pkgconf gtk3 gstreamer gst-plugins-base gst-plugins-good gst-libav mpv libepoxy
flutter config --enable-linux-desktop
flutter doctor -v
flutter pub get
flutter build linux --release
```

Аудиобэкенду нужен GStreamer, видеобэкенду — libmpv. В Arch пакет
[`mpv`](https://archlinux.org/packages/extra/x86_64/mpv/files/)
содержит `libmpv.so` и `mpv.pc`. Первая сборка также может скачать mimalloc,
используемый нативным видеобэкендом.

Для x64 результат находится в `build/linux/x64/release/bundle/`.
Запуск: `./build/linux/x64/release/bundle/music_player`.
Переносите весь `bundle`, сохраняя папки `lib` и `data`.

## Проверка изменений

```bash
flutter analyze
flutter test
```

В репозитории есть тесты плейлистов, текстов, обновлений библиотеки,
резервных копий, статистики и Discord-интеграции. Нативный звук, видео
и интеграции также проверяйте на целевой ОС.
